## Intent

**Problem:** Two halves of the same gap left by `spec-pure-util-doctest-session`. (DW-104) `app/utils/sql_text.py` states the exact `%`/`_`/`\` replacement semantics, the replacement *ordering* guarantee and the deliberate non-idempotency of `escape_like_literal` entirely in prose, with zero `>>>` examples — the module with the subtlest semantics contributes nothing to the `doctests` session that now covers its package, while its one function is load-bearing (imported by `app/utils/category.py:59`) and actively changing. (DW-103) Nothing stops a `>>>` example added to a route, service or model docstring from becoming unexecuted documentation: `nox -s doctests` runs `--doctest-modules` against `app/utils` only, and no test or warning says so.

**Approach:** Write `>>>` examples for `escape_like_literal` covering each metacharacter, the escape character itself, and the ordering/non-idempotency guarantee — collected automatically by the existing session with no `noxfile.py` change. Separately add a cheap unit-test tripwire that scans the non-`app/utils` Python sources for doctest prompts and fails with a pointer to the `doctests` session, plus a guard that the session still targets `app/utils` so the tripwire's exclusion stays true.

## Boundaries & Constraints

**Always:**
- The new examples describe behavior `escape_like_literal` already has. They are added to its docstring only; `LIKE_ESCAPE_CHAR`, `is_storable_text` and the module docstring keep their current text.
- Expected-output lines must be readable as the escaped text itself, not as a doubled `repr`. Use `print(...)` in the examples and make the docstring a raw string (`r"""`), converting its existing `\\` prose escapes to single backslashes so the rendered docstring is byte-identical apart from the added examples.
- The tripwire fails with a message naming every offending `path:line` and pointing at `nox -s doctests` and the `app/utils/` boundary, so the reader learns *why* it is red without opening the spec.
- The tripwire lives in `tests/unit/`, carries `@pytest.mark.unit` (registered in `pytest.ini`; `--strict-markers` is in force), and runs in `nox -s tests`.

**Block If:**
- An added example fails because the code disagrees with the documented prose. Report the discrepancy; do not change `escape_like_literal`'s behavior to make an example pass.

**Never:**
- Do not widen the `doctests` session's path argument or add `--doctest-modules` to `pytest.ini` `addopts` — running it tree-wide imports the Flask/ORM layers, which the source story's intent rules out.
- Do not add `# doctest:` directives (`SKIP`, `ELLIPSIS`, …) or delete an existing example.
- Do not scan `tests/` in the tripwire: examples there are not published contracts, and the tripwire's own source contains the pattern it searches for.
- Do not edit `_bmad-output/implementation-artifacts/deferred-work.md`.
- Do not modify `pytest.ini`, `noxfile.py`, or `.github/workflows/test.yml`.

|----------|--------------|---------------------------|----------------|
| Nothing to escape | `escape_like_literal('plain text')` | `plain text` — unchanged | No error expected |

## Design Notes

`escape_like_literal` returns text containing backslashes, so the example form matters. A bare expression prints the `repr`, which doubles every backslash: `escape_like_literal('10%')` displays as `'10\\%'` while the value is `10\%` — the doubling is the repr's, not the function's, and this docstring's whole subject is which backslashes the function inserted. `print(...)` shows the real string, and a raw docstring lets the expected-output line be typed exactly as it appears. Input literals still spell a backslash as `\\` inside the example source, because doctest compiles that line as Python and an unrecognized `\p`-style escape is a `SyntaxWarning` on 3.13.

Scope of the tripwire's scan is the Python that could plausibly carry a published contract docstring and is not covered by the session: everything under `app/` outside `app/utils/`, plus the five repo-root modules. Everything else in the repo is unscanned by that reach alone — there is no exclusion list in `_scanned_files`. (Corrected across two review passes. Pass 1's draft justified excluding `tests/` by claiming the tripwire would match its own source; it would not, since the pattern matches a prompt only at the start of a line. Pass 2 found the replacement still wrong in a subtler way: it framed `migrations/` and `tests/` as *deliberate exclusions* and `hooks/`/`_bmad/` as an unscanned *boundary*, implying a filtering mechanism the code does not contain — `migrations/` sits at the repo root, so it is out of scope for exactly the same structural reason `hooks/` is, and a reader looking for the exclusion in `_scanned_files()` would not find one. The docstring now states the single reach first and gives the per-tree reasons as commentary on it.) Those reasons still differ in kind and are worth keeping: an example in `tests/` describes the test rather than a caller-facing contract, `migrations/` is Alembic-generated, and `_bmad/scripts/`/`.bmad-loop/` were simply not in view. `hooks/` no longer appears in either document as an example — it contains no Python at all, so it can never carry a prompt.

The guard test reads `noxfile.py` structurally, and pass 2 tightened every step of that reading after finding each one accepted something it claimed to reject. The flag was matched in *any* call rather than a `.run(...)` one, so the `session.log` the comment named as the thing it excluded would in fact have satisfied it. Every non-flag argument was treated as a path, so `-m`, `"not slow"` — a form three other sessions already use — would have been reported as a second path argument, blaming the session's scope for an unrelated flag. Any decorator counted as a nox session decorator. The session was located by function name while nox resolves a decorator's `name=` first. And `nox.options.sessions` was matched on any attribute called `sessions`, in one syntactic form, with *absence* of the assignment treated as failure — though an unset option makes nox run every session, doctests included. A fifth failure mode was added rather than argued away: `--doctest-modules` migrating into `pytest.ini`'s `addopts`, which `noxfile.py`'s own docstring warns against, widens doctest coverage to every session without touching the session the guard reads.

Pass 3 continued in the same direction but hit a different class of defect, worth recording because it changes what "hardening" means here. Passes 1 and 2 found the guard accepting things it claimed to reject — false negatives. Pass 3's one medium is the inverse: the `pytest.ini` text scan pass 2 added rejects something it should accept, because it reads the file's *comments* as if they were configuration, in a file that is heavily commented about its own options.
